# Skill 与 Knowledge 架构

## 目标

将重型 Coze Skill 拆分为轻量执行方法和可检索知识，减少 Prompt 体积、延迟、成本、超时和输出漂移。

## 目录

```text
.agents/skills/
  <skill>/SKILL.md
  <skill>/agents/openai.yaml

knowledge/
  catalog.json
  <collection>/
    references/
    rules/
    foundations/
    techniques/
    templates/
```

Skill 不保存大段案例、规则全文或行业资料，只说明：

- 何时触发
- 需要什么输入
- 执行步骤
- 何时检索哪个知识集合
- 召回数量和上下文预算
- 输出格式和风险纪律

## 知识类型

### 通用知识

项目维护的方法论、平台规则、通用案例和模板。存放于 `knowledge/`，可以跨客户复用。

### 租户知识

客户公司资料、品牌口径、产品信息、历史内容和内部材料。未来存入数据库或对象存储，并通过 `tenant_id` 强制隔离。

### 实时数据

新闻、热点榜单、社交讨论和监管动态。必须带来源、发布时间、抓取时间和有效期，由实时数据层缓存，不混入长期向量库。

## 运行时编排

```text
用户请求
  -> 任务分类与 Skill 路由
  -> 元数据过滤
  -> 混合检索
  -> 去重与重排
  -> 上下文预算控制
  -> 模型结构化输出
  -> Schema 校验
  -> 页面展示
```

热点选题示例：

1. 实时数据层获取近三日候选热点。
2. `trend-hotspot-pool` 使用少量质量和风险知识完成清洗。
3. `pr-expert` 召回品牌策略与受众知识，筛选 TOP5。
4. 模型仅接收结构化候选、企业资料和少量相关知识片段。

## 检索规则

- 先过滤 Skill、行业、平台、地区、知识类型和时效等级。
- 默认使用关键词与向量混合检索。
- 同一文档最多保留两个片段，避免单一资料占满上下文。
- 片段必须附带来源路径和标题层级。
- 不足时返回知识缺口，不使用无关片段凑数。
- 法规和当前市场信息必须额外核验实时来源。

## 稳定性收益

- Skill 注入量从数万字下降到约 2KB。
- 每次请求只加载 2-6 个相关片段。
- 模型更容易遵守核心任务和输出 Schema。
- 知识更新无需重新发布 Skill。
- 客户资料可以独立隔离和删除。
- 可记录每个片段对结果的影响，便于调试和审计。

## 后续工程实现

第一版建议使用 PostgreSQL：

- 文档元数据和租户权限存普通表。
- 文本片段和 embedding 存 pgvector。
- 原始大文件存对象存储。
- 实时热点使用带 TTL 的独立表或 Redis 缓存。
- 检索服务统一执行过滤、召回、重排和 Token 预算。
