# Knowledge System

本目录存放可按需检索的知识，不随 Skill 默认加载。

## 分层

- `.agents/skills/`：角色、工作流、知识选择规则和输出纪律。
- `knowledge/`：通用方法、规则、案例、模板和历史资料。
- 未来 `tenant-knowledge/`：客户私有资料，必须按租户隔离。
- 未来 `live-data/`：新闻、热点和舆情等带时间戳的实时数据。

静态知识不能替代实时数据，通用知识不能泄露或覆盖客户私有资料。

## 检索流程

1. 根据 Skill、任务类型、行业、平台、地区和日期生成过滤条件。
2. 先做元数据过滤，再执行关键词与向量混合检索。
3. 合并相邻片段，去除重复内容。
4. 按相关性、权威性、时效性和多样性重排。
5. 只向模型传递任务直接需要的片段及来源信息。

## 切片建议

- Markdown 按标题和段落切片，不按固定字符粗暴截断。
- 建议每片 300-700 tokens，重叠不超过 80 tokens。
- 表格、检查清单和模板尽量保持完整。
- 每个片段保存 `document_id`、标题路径、标签、更新时间和来源路径。

## 上下文预算

- 简单规则查询：1-3 个片段，最多 2,000 tokens。
- 普通分析：3-6 个片段，最多 6,000 tokens。
- 复杂报告：分阶段检索，不一次注入超过 8,000 tokens。
- 超出预算时先摘要和去重，不直接扩大模型上下文。

## 时效

- `stable`：方法论和基础模型，低频复核。
- `review`：平台规则、媒体格局和案例，定期复核。
- `volatile`：法规、行业趋势和舆论环境，使用前核验最新来源。
- `live`：热点和新闻，不存入本静态目录，由实时数据层管理。

## 索引入口

机器可读配置见 `catalog.json`。当前目录是源文件层，未来可由独立索引任务同步到 PostgreSQL/pgvector 或其他检索服务。
